Koottam (കൂട്ടം) · Malayalam for "a gathering" · a measured AI experiment

Is a crowd of AI models smarter than its best member?

Four open-weight models, each on a different server, answer the same 616 security questions and vote. Then the crowd's agreed answers train one small model that runs on a laptop. Nothing is assumed. Each claim is scored on held-out questions.

Measured: supported

2. A small model trained on the council beats its untrained self

Gemma 3 1B went from 60.4% to 66.7% on the same 616 questions (p = 0.008). Almost all of the gain is prompt-injection detection.

How it works

Every server speaks the same OpenAI-compatible API, so one async client drives all of them. One member per provider is deliberate: free tiers cap requests per day, per account.

Results: 616 held-out questions

500 questions from the published CyberMetric-500 security benchmark, plus 116 prompt-injection examples (is this text an attack on an AI assistant?). No test question, or near-copy of one, is in training.

What the data showed

98.7%

The right answer was almost always in the room

On 608 of 616 questions at least one member was right. Knowledge wasn't the bottleneck. Choosing whom to believe was.

32×

Correlated mistakes outvote the best member

gpt-oss and Qwen gave the same wrong answer 32 times. On 9 questions the best model was the only one right, and equal votes simply outvoted it. A council needs members that fail differently. Diversity of model family is necessary, not sufficient.

~40%

Weighting votes closes part of the gap

Each vote counts log(p(k−1)/(1−p)), the optimal rule for independent voters (Nitzan–Paroush). The weights were learned from training questions only; tuning them on the test set would only memorise the answer key. Result: 92.9% → 93.5%, with no tie-breaks needed.

~7%

The training key is noisy

On ~7% of training questions, three or more models agreed against the answer key. Spot checks found real key errors. The training filter keeps an example only when the council and the key agree, so the student never learns a disputed answer.

What the student showed

Gemma 3 1B, LoRA-trained for 9.6 minutes on a free T4 with 2,094 council-agreed answers, against the same model untrained. Both are exported and served identically, so the weights are the only difference.

123:84

Measured paired, not eyeballed

Both students answered the same 616 questions. Only the flips count: the student got 123 right that the base missed, and missed 84 the base got right. If they were equally good, that split would happen by chance 0.8% of the time (exact McNemar test). The gain is +6.3 points, 95% interval +1.8 to +11.0.

113/116

The base was crying wolf

Untrained, it called 113 of 116 texts a prompt injection, so its 49.1% on injection was just the share of attacks. Trained, it recognises 52 of 56 safe texts: injection rose to 76.7%. Security knowledge barely moved (+1.4 points, p = 0.61). The fine-tune changed behaviour, not knowledge. In detection terms, precision (how many flags were real) went from 50% to 90%, while recall (how many attacks were caught) went from 95% to 62%.

37/60

The filter taught it to lean "safe"

The agreement filter kept all 78 safe injection examples but only 37 of 50 attacks, because models disagree more about attacks. Trained on 68% "safe", the student now misses 23 of 60 real attacks: 62% recall. An agreement filter is not neutral about labels. Run 2 rebalances it, and its first pass mark is recall clearly above 62% with precision near 90%.

−11 pts

It inherits the council's blind spots

On security questions all four members got right, the student improved (69.5% → 73.3%). Where two or fewer were right, it got worse (37.1% → 25.7%). Distillation copies the mistakes too.

Engineering

Four free tiers, four sets of limits

Per-model request pacing (fractional req/min) plus an in-flight cap, and retry on 429/5xx with Retry-After and backoff. Total model spend: $0.

Resumable by design

Every answer is cached, keyed by the model's fingerprint (id + settings). Runs survive rate limits, sleep and shutdown; scoring the council costs no extra calls.

No test leakage

Exact and near-duplicate (≥80% word overlap) removal between train and test. This caught a typo'd copy of a test question hiding in the training pool.

Built to be checked

Python 3.11, pydantic v2, mypy strict, ruff, 26 offline tests. gitleaks runs pre-commit and in CI over the full history.

  6. Done: claim 2 scored: 60.4% → 66.7%, supported; the gain is injection detection

Scope, deliberately: defensive security and prompt-injection detection only. No offensive tooling in the training data.
