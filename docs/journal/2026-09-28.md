# 2026-09-28: Weighted votes, first training examples

The 500-question train run was paused at 01:50 (laptop off overnight) and resumed at 14:24.
Every answer was cached, so only gpt-oss's last ~130 questions were asked. It finished at
15:22.

## Results

- **Training set:** 417 examples kept from 500 questions (≥3 of 4 agree **and** the key
  agrees): 395 security, 22 injection. Written to `data/sft.jsonl`.
- **Weights, learned on 499 train questions:**

  | Member | Security weight | Injection weight |
  |---|---|---|
  | gpt-oss | 2.88 | 0.74 |
  | Qwen | 2.93 | 0.89 |
  | Gemma 31B | 3.06 | **1.91** |
  | laptop Gemma | 2.12 | 1.43 |

- **Weighted council on the test set: 93.5%**, against 92.9% for equal votes and 94.3% for
  Gemma 31B. That closes ~40% of the gap, but it still doesn't beat the best member. It
  needed no tie-breaks, because real-valued weights almost never tie.
- **The training answer key is noisy.** 44/500 questions had ≥3 members agreeing against
  the key, 16 of them unanimously. Spot checks found real key errors (Split Knowledge vs
  Two-Person Control; RSA blocks as a "decimal string") and some genuinely ambiguous ones
  (PCI DSS 11.6.1 allows two frequencies). This explains the ~86% train vs ~94% test
  accuracy gap. The key-match filter drops these, which is correct: contested answers
  shouldn't be taught.

## Corrections

- My earlier "~50 h on the laptop for 3,000 questions" assumed the old, slow speed. At
  ~12 s/question it's ~10 h. The real bottleneck is Cerebras (150/hour, 2,400/day, so ~20 h
  over two days). **No AWS GPU is needed for the build**, and the fine-tune can use a free
  Kaggle/Colab GPU. The parked AWS question is dropped.
- `build` now takes a prefix of one fixed shuffle, so a bigger build reuses a smaller one's
  answers. `random.sample` switches algorithm with k, so it didn't guarantee that.
