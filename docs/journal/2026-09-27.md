# 2026-09-27: The council moves to four servers

**Trigger:** Roshan made an OpenRouter key and saw "Key limit $100" and thought it wasn't
free. It is: that figure is a spending cap, the key reports `is_free_tier: true`, and with
0 credits nothing can be billed.

**The real problem**, read from `GET /api/v1/key`: the free tier allows **50 requests a
day**. The first design put three roles on OpenRouter, which would have made scoring the
616 test questions a ~37-day job.

**Decision (Roshan):** stay at $0 and spread the council across free providers, with one
member each:

| Member | Server |
|---|---|
| gpt-oss-120b | Cerebras |
| Llama 3.3 70B | Groq |
| Gemma 4 31B | Google AI Studio |
| Gemma 4 E2B | the laptop |

OpenRouter only breaks ties. Rejected: a $10 credit top-up, and shrinking the test set.

## Also found

- OpenRouter's `:free` Qwen and Gemma returned 429 "rate-limited upstream" with
  `limit_source: upstream_provider_shared_pool`. That pool is shared by *all* free users,
  so it's not our quota. The tie-breaker moved to Nemotron 3 Super, whose pool answered.
- `build` no longer calls the tie-breaker. A tie holds at most half the votes, so it can
  never reach `min_agree`, and the config loader now enforces min_agree > half so this
  stays true.
- Bug fixed: the `replace-me` placeholder counted as a key and produced 401s.
- **Key hygiene:** the OpenRouter key was pasted into `.env.example`, which is committed.
  It was moved to `.env` before any commit, and git history is clean. `.env.example` now
  says in its first line that keys never go there.
